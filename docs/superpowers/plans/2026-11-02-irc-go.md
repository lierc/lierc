# Replace liercd's IRC client with irc-go — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** liercd's connections run on `github.com/ergochat/irc-go` v0.7.0, so no line from a server can panic liercd, while everything liercd publishes keeps its shape.

**Architecture:** Each connection attempt is a fresh `ircevent.Connection` dialed through our guarded dialer. One raw callback turns every incoming line into today's `IRCMessage`, runs our channel-state handlers under the client lock, and publishes after unlocking. We drive reconnects (our backoff) and rate-limit our own sends; irc-go does parsing, CAP, SASL, registration, pings and nick-in-use at registration.

**Tech Stack:** Go 1.27, `github.com/ergochat/irc-go` v0.7.0 (`ircevent`, `ircmsg`), `golang.org/x/time/rate`.

**Spec:** `docs/superpowers/specs/2026-11-02-irc-go-design.md`

## Global Constraints

- All work in `pkg/lierc` and `pkg/liercd` of the lierc repo, on branch `irc-go` off `master`, after the user has committed the current uncommitted config-change work. Commit per task on the branch; never push.
- irc-go pinned at exactly `v0.7.0`.
- JSON shapes unchanged: `IRCMessage` (`Prefix{Name,User,Server,Self}`, `Tags`, `Command`, `Raw`, `Time`, `Params`, `Direct`), `IRCClientData` minus `Caps`, `IRCClientStatus`, `IRCClientMultiMessage`, `IRCConfigChange`.
- Global channels `Events`, `Multi`, `Status`, `ConfigChanges` keep their names and types. Every message goes to `Events`; QUIT and NICK additionally go to `Multi` (as today).
- Status messages, verbatim: `Connecting`, `Connected`, `Reconnecting in <duration>` (e.g. `Reconnecting in 15s`), `Closing connection`, or the error text.
- Backoff: `min(15s × retries, 300s)`; retries reset on 001.
- Send limit: `rate.NewLimiter(1, 4)`.
- `Timeout` 2m, `KeepAlive` 4m, `MaxLineLen` irc-go default, `RequestCaps` `echo-message`, `message-tags`, TLS `InsecureSkipVerify: true`, SASL mech `PLAIN`.
- Channel and nick keys stay `strings.ToLower`.
- Every handler checks `len(m.Params)` before indexing.
- No handler holds the client lock while sending on a global channel.
- Never write to the map `ISupport()` returns.
- Done means `go vet ./...` and `go test -race ./...` are clean.

## Review Focus

1. **Server drops the connection during registration (before 376/422).** `Connect()` errors; expect a disconnected status, `Reconnecting in 15s`, a reconnect, and no leaked goroutine. Pinned in Task 5 (`TestDropDuringRegistrationReconnects`).
2. **`Destroy` while sleeping between attempts, or while `Connect()` is still registering.** Expect it to return within ~2s and no reconnect afterwards. Pinned in Task 5 (`TestDestroyWhileSleeping`, `TestDestroyDuringRegistration`).
3. **Raw lines and NICK from the API while disconnected.** Expect them to be dropped (as today) without panic or block. Pinned in Task 6 (`TestChangeNickWhileDisconnected`) and Task 4 (`TestSendWhileDisconnected`).

5. **Synthetic events with empty pieces** (`Host` empty in `ConnectEvent`, `User`/`Host` empty before the first self-JOIN in `PrivmsgEvent`). Connection per attempt (`c.connect()`, run in its own goroutine):
1. Build an `ircevent.Connection` from the spec's table, with these fields:
   - `Nick: c.Config.Nick`
   - `User` and `RealName`: `Config.User`, or `Config.Nick` when that's empty
   - `Password` when not SASL
   - SASL fields when SASL
   - `RequestCaps`
   - `Timeout: ircTimeout`, `KeepAlive: ircKeepAlive`
   - `QuitMessage: "bye"`
   - `DialContext: dialer(Exempt(c.Config), c.Config.Ssl, onConnected)`
   - `Log: log.New(os.Stderr, c.Id+" ", log.LstdFlags)`
   - `Debug: c.debug > 1`
2. `AddRawCallback(c.onLine)` and `AddDisconnectCallback(c.onDisconnect)`.
3. Store it as `c.conn` under the lock and call `conn.Connect()`.
4. `onConnected(sock)` stores `c.socket` and sets the status to `Connected`.
5. If `Connect()` returns an error, close `c.socket`, set the disconnected status to `err.Error()`, and call `c.endAttempt()`.
6. `onDisconnect` runs `go conn.Quit()` so irc-go's reconnect loop exits, closes the socket, sets the disconnected status, and calls `c.endAttempt()`. The message is the first read or write error seen by the tracked socket, or `Disconnected` when none was recorded. Wrap the dialed conn to record it.
7. `endAttempt()` closes `attemptDone`. Unless quitting, it increments `Retries` and sets the status to `Reconnecting in <backoff>`. After `backoff(Retries)` it calls `c.connect()` again, through a `time.AfterFunc` kept in `c.timer`.
8. Status changes go through `c.setStatus(connected bool, msg string)`: update under the lock, take a snapshot, unlock, then `Status <- snapshot`.

`onLine(raw string, m ircmsg.Message, err error)`:
- On err, log and return.
- Otherwise `msg := newIRCMessage(raw, m)`, `e := c.Message(msg)`, `c.publish(msg, e)`.
